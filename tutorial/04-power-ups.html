Lesson 4 — Customize power-ups (Snake-specific) ​

Goal: add 22 toggles to your mod (one per Snake power-up) that the player can enable/disable individually, plus a slider controlling the global spawn frequency. Canonical pattern: array of definitions → auto-generated UI.

Disclaimer: this lesson is specific to Snake Classic. Every mod-compatible game exposes its own tunables. What you learn here (array→UI pattern, callHostFn per toggle, preset that applies a set) is transferable — only the names change.

1:1 reference code: studio.fun-config does exactly what this lesson teaches, in production.

The Snake power-up catalog ​

Snake Classic has 22 power-ups. Each is controlled by a boolean tunable powerup<Name>Enabled. If it's false, that power-up doesn't appear during play.

Plus an extra tunable powerupIntervalMs (number, 1000-30000) that controls how often a new power-up appears.

1 — Define the toggle array ​

src/toggles.ts:

ts
export interface PowerUpToggle {
  binding: string;
  i18nKey: string;
  fallback: string;
}

export const POWER_UP_TOGGLES: PowerUpToggle[] = [
  { binding: 'tunables.powerupSpeedBoostEnabled',
    i18nKey: 'mymod.powerups.speedBoost', fallback: 'Speed Boost' },
  { binding: 'tunables.powerupInvincibilityEnabled',
    i18nKey: 'mymod.powerups.invincibility', fallback: 'Invincibility' },
  { binding: 'tunables.powerupDoublePointsEnabled',
    i18nKey: 'mymod.powerups.doublePoints', fallback: 'Double Points' },
  // … 19 more
  { binding: 'tunables.powerupTimeTravelEnabled',
    i18nKey: 'mymod.powerups.timeTravel', fallback: 'Time Travel' },
];

The "array of definitions" pattern is the foundation. If the game adds a new power-up in a future version, you just extend the array.

2 — Build the tab dynamically ​

src/settings-tab.ts:

ts
import { POWER_UP_TOGGLES } from './toggles';

function t(key: string, fallback: string): string {
  return host.i18n?.t(key) ?? fallback;
}

export function buildSettingsTab() {
  const toggleChildren = POWER_UP_TOGGLES.map((toggle) => ({
    kind: 'toggle' as const,
    label: t(toggle.i18nKey, toggle.fallback),
    binding: toggle.binding,
  }));

  return {
    id: 'mymod-powerups',
    title: t('mymod.tab.title', 'Power-Up Mixer'),
    icon: 'extension',
    sections: [
      {
        kind: 'card',
        title: t('mymod.section.spawn', 'Frequency'),
        children: [{
          kind: 'slider',
          label: t('mymod.spawn.label', 'Interval between power-ups (ms)'),
          min: 1000,
          max: 30000,
          step: 500,
          binding: 'tunables.powerupIntervalMs',
        }],
      },
      {
        kind: 'card',
        title: t('mymod.section.toggles', 'Active power-ups'),
        children: toggleChildren,
      },
    ],
  };
}

Each toggle with binding: 'tunables.powerup<X>Enabled' is connected automatically: when the player flips it, the runtime calls gameConfigSet({ name: 'powerup<X>Enabled', value: true|false }) with no code from you.

src/index.ts:

ts
import { buildSettingsTab } from './settings-tab';

host.registerSettingsTab?.(buildSettingsTab());

host.log.info('[mymod] Power-up mixer loaded.');

4 — Presets: apply a full set at once ​

Typical pattern: 3 buttons "Classic / Casual / Hardcore" that apply predefined combinations.

src/presets.ts:

ts
export type PresetName = 'classic' | 'casual' | 'hardcore';

export const PRESETS: Record<PresetName, Record<string, boolean | number>> = {
  classic: {
    powerupSpeedBoostEnabled: true,
    powerupDoublePointsEnabled: true,
    powerupExtraLifeEnabled: true,
    // rest false
    powerupIntervalMs: 8000,
  },
  casual: {
    // all benign power-ups ON
    powerupSpeedBoostEnabled: true,
    powerupInvincibilityEnabled: true,
    powerupMagnetEnabled: true,
    powerupGoldenAppleEnabled: true,
    powerupExtraLifeEnabled: true,
    powerupRainbowHeartEnabled: true,
    powerupIntervalMs: 5000,
  },
  hardcore: {
    // only hostile challenges
    powerupBombPickupEnabled: true,
    powerupBlindfoldEnabled: true,
    powerupDemonEnabled: true,
    powerupTimeTravelEnabled: true,
    powerupIntervalMs: 3000,
  },
};

Buttons in the tab:

ts
{
  kind: 'card',
  title: t('mymod.section.presets', 'Presets'),
  children: [
    {
      kind: 'button',
      label: t('mymod.preset.classic', 'Classic'),
      variant: 'primary',
      action: { kind: 'event', name: 'MYMOD_APPLY_PRESET',
        payload: { preset: 'classic' } },
    },
    {
      kind: 'button',
      label: t('mymod.preset.casual', 'Casual'),
      variant: 'secondary',
      action: { kind: 'event', name: 'MYMOD_APPLY_PRESET',
        payload: { preset: 'casual' } },
    },
    {
      kind: 'button',
      label: t('mymod.preset.hardcore', 'Hardcore'),
      variant: 'secondary',
      action: { kind: 'event', name: 'MYMOD_APPLY_PRESET',
        payload: { preset: 'hardcore' } },
    },
  ],
}

Handler:

ts
import { POWER_UP_TOGGLES } from './toggles';
import { PRESETS, type PresetName } from './presets';

host.subscribeEvent('MYMOD_APPLY_PRESET', async (payload) => {
  const name = (payload as { preset?: string })?.preset as PresetName;
  if (!PRESETS[name]) return;

  // 1. Reset ALL toggles to false (clean state).
  for (const toggle of POWER_UP_TOGGLES) {
    const tunableName = toggle.binding.replace(/^tunables\./, '');
    await host.callHostFn('gameConfigSet', {
      name: tunableName, value: false,
    });
  }

  // 2. Apply the preset (only the keys it defines).
  for (const [name, value] of Object.entries(PRESETS[name])) {
    await host.callHostFn('gameConfigSet', { name, value });
    // Persist so the UI toggles reflect the state.
    await host.storage?.set(`tunables.${name}`, value);
  }

  host.dispatch('MOD_NOTIFICATION', {
    text: `Preset "${name}" applied.`,
    kind: 'success',
  });
});

Extra permissions:

json
{
  "type": "events",
  "subscribe": ["MYMOD_APPLY_PRESET"],
  "dispatch": ["MOD_NOTIFICATION"],
  "rationale": "Reacts to preset buttons and notifies the player."
}

5 — Performance: apply in bulk ​

Each callHostFn crosses the sandbox boundary and costs ~0.5-1 ms. Applying a preset does 22 calls (reset) + N calls (apply). To avoid freezing the UI:

ts
// Fire all promises and wait with Promise.all
await Promise.all(
  POWER_UP_TOGGLES.map((t) =>
    host.callHostFn('gameConfigSet', {
      name: t.binding.replace(/^tunables\./, ''),
      value: false,
    })
  )
);

Goes from ~22 ms serial to ~3-5 ms parallel. Valid pattern when host calls are idempotent (order doesn't matter) — as it is here.

6 — Caveat: target.gameId ​

This mod only works in Snake Classic. If you activate it in another framework game (Dices & Destiny, Pong…), callHostFn for Snake-specific tunables rejects with not-found. That's why you declare:

json
"target": { "gameId": "snake-classic", "gameVersion": "^1.0.0" }

The loader refuses to activate the mod if gameId doesn't match. Zero silent crashes.

What you've learned ​

  • Array → auto-generated UI pattern — 22 toggles from a 22-definition array.
  • binding: 'tunables.<name>' connects automatically without a handler.
  • Presets as event + handler applying N tunables in bulk with Promise.all.
  • target.gameId prevents cross-game activation.
  • host.dispatch('MOD_NOTIFICATION') to confirm to the player.
